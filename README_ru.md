# ml1250 — Samsung ML-1250 на Windows 10/11 x64

[English](README.md) · **Русский**

Драйвер принтера Samsung ML-1250 для актуальных Windows и набор утилит
для диагностики и печати в обход системной очереди.

> [!WARNING]
> **Vibecoded.** Проект в основном написан ИИ-ассистентом под руководством
> человека: код, драйвер, исследование и этот текст. Всё, что перечислено в
> разделе [«Что проверено»](#что-проверено-а-что-нет), действительно
> проверено, в том числе на живом принтере, но классического ревью кода
> человеком не было. Используйте на свой риск. Установщик добавляет
> самоподписанный сертификат в доверенные корневые — прочитайте
> [«Про подпись»](#про-подпись--прочитайте-это-важно) перед запуском.

## Главное: ML-1250 — не GDI-принтер

Почти всё, что пишут в интернете про «самсунги той эпохи», к ML-1250
не относится, и именно поэтому подбор драйверов заходит в тупик.
Сервис-мануал серии ML-1200 (`ML-1210 / ML-1250 / ML-1220M`) даёт таблицу:

| | ML-1210 / ML-1220M | **ML-1250** |
|---|---|---|
| Resolution | 600 × 600 | **1200 × 600** |
| Controller | Jupiter | **отдельная плата** |
| Memory | 8 MB Equivalent | **4 MB** |
| **Emulation** | **SmartGDI** | **PCL6** |

В мануале для них разные блок-схемы — «GDI Block Diagram (ML-1210/ML-1220M)»
и «PCL Block Diagram (ML-1250)» — и разные платы контроллера:
`PBA MAIN-CONTROLLER PCL, JC92-01333A` стоит только в ML-1250.

Пользовательский мануал подтверждает: `Emulation: PCL6`,
`Fonts: 1 bitmap, 45 scalable` (это настоящий интерпретатор, а не
host-based растеризация на стороне ПК), `RAM: 4 MB`. На панели принтера
есть отдельное меню **PCL 5e** (Typeface, Symbol Set, Pitch, Lines Per
Page, Point Size, Courier), а инструкция по Linux прямо велит выбирать
в `printtool` тип принтера **«Samsung Printer PCL 5e Compatible»**.

Решающее подтверждение — **оригинальный драйверный CD Samsung**
(`ML_1250_250.iso`, part no. JC46-00127A, 2002; лежит на archive.org).
На нём:

* только каталог `PCL/` — ни следа GDI/SPL-драйвера;
* `ML125.INI`: `[Protocol Class] 0=1.1 1=2.0` — это классы протокола
  PCL-XL, которые умеет интерпретатор;
* `ML125.DDF` с комментарием `// "Folio": undefined in PCL-XL`;
* `USB/SSUSB.INF`: `USB\VID_04E8&PID_300E ;ML-1250`
  (для сравнения `PID_300C` — это ML-1210);
* `LINUX/SSPRT.DB` — собственная таблица Samsung «эмуляция → устройство
  Ghostscript». ML-1250 числится в `SECPCL6 / GSDriver: pxlmono`
  **и** в `SECPCL5 / GSDriver: ljet4`, и его **нет** в
  `SECPRT / GSDriver: gdi` («PrinThru Compatible»), куда попали
  настоящие host-based модели.

То есть **сам Samsung предписывает для ML-1250 драйвер `ljet4`, то есть
PCL5e**. Ровно это здесь и сделано.

> Единственный источник против — README проекта splix: «older SPL1-based
> models (**ML-12xx**, ML-14xx) do not work. Use these printers with the
> older "gdi" driver». Но это шаблон по маске `ML-12xx`, а не разбор
> конкретной модели, и он противоречит и сервис-мануалу, и диску
> производителя. У ML-1250 просто другая плата контроллера.

Ещё одна поправка к спецификации: `1200 × 600` в таблице — это
маркетинговый «1200 dpi class». Механизм печати — **600 × 600** плюс
сглаживание SRT. Генерировать растр надо в 600 или 300 dpi, никогда не
в 1200.

### Почему ничего не заводилось

1. **Родного x64-драйвера не существует.** Сервис-мануал перечисляет
   поддерживаемые ОС: `Windows 95/98/2000/Me/NT`. 32-битный v3-драйвер
   принципиально не ставится на x64 Windows — спулеру нужен нативный
   бинарник.
2. **Универсальные драйверы говорят на слишком новом PCL.** Samsung UPD,
   HP UPD и встроенный «Microsoft PCL6 Class Driver» генерируют PCL-XL
   Protocol Class 3.0. В ML-1250 интерпретатор классов 1.1/2.0
   двухтысячного года — отсюда пустые листы и страницы
   `PCL XL error, Subsystem: KERNEL`.
3. **4 МБ памяти.** Страница A4 600 dpi — это ~4,3 МБ несжатого растра.
   Современные драйверы об этом не подозревают.
4. **Windows не может подобрать драйвер сама.** Ранжирование встроенных
   class-драйверов опирается на ключ `CID:` в IEEE-1284 device ID —
   расширение Microsoft, появившееся после 2012 года. У принтера 2000
   года его, разумеется, нет.

**Вывод:** принтер надо кормить консервативным **PCL5e-растром**. Это
ровно тот диалект, с которым он продавался.

### Драйвер: INF + GPD, без единой строчки бинарного кода

Это **v3 Unidrv minidriver**. Всю работу — растеризацию, полутона,
разбиение на полосы, сжатие растра — делает встроенный в Windows
`unidrv.dll`; наш `ml1250.gpd` только описывает, какие байты понимает
принтер. В спулер не загружается ничего стороннего, и один и тот же
пакет работает на x64 и на Arm64, потому что компилировать нечего.

Структура INF скопирована с микрософтовского `prnge001.inf` — INF
встроенного драйвера «Generic / Text Only», который сам является таким же
GPD-only Unidrv-минидрайвером. Отсюда современная форма
`CoreDriverSections` вместо устаревшей `Include=ntprint.inf` / `Needs=`.

Ключевые решения в GPD и почему:

* **PCL5e, а не PCL6.** Меньший, старше и предсказуемее.
* **Никаких device fonts** — Unidrv растеризует весь текст. Медленнее,
  но кириллица и любые шрифты печатаются ровно так, как на экране,
  без сюрпризов с symbol set и подстановкой.
* **Объявлены и `CmdEnableTIFF4`, и `CmdEnableDRC`** — Unidrv сжимает
  каждую строку обоими способами и оставляет тот, что короче.
* **`BadCursorMoveInGrxMode` объявлен для всех четырёх направлений.**
  PCL прямо запрещает что-либо, кроме передачи данных, смены метода
  сжатия и Y-offset, пока идёт растр: любая другая команда неявно
  завершает изображение. Без этой строки Unidrv вставил бы между полосами
  `<Esc>*p` и молча порвал бы картинку; с ней он корректно закрывает
  растр, двигает курсор и открывает новый. По той же причине
  `StripBlanks` ограничен `LEADING, TRAILING` — пробел в середине строки
  в растровом режиме перепрыгнуть нечем.
* **Полутон по умолчанию `HT_PATSIZE_6x6_M`** (кластерный дизер).
  Это не про красоту: кластерные узоры дают длинные серии одинаковых
  байтов, а рассеивание ошибки HP прямо называет случаем, с которым
  внутреннее сжатие PCL5-принтера не справляется. Замерено на странице
  A4 600 dpi с градиентом (несжатый растр — 3 979 376 байт):

  | полутон | размер задания |
  |---|---|
  | кластерный дизер | **182 522** |
  | рассеивание ошибки | **3 705 322** |

  Двадцатикратная разница. На принтере с 4 МБ это ровно граница между
  напечатанной страницей и `print overrun`.
* **300 dpi — полноценная опция, а не запасной выход.** Драйвер шлёт
  ещё и `@PJL SET RESOLUTION=300`, так что буфер страницы в принтере
  становится вчетверо меньше. Это первое, что нужно переключить, если
  сложная страница не печатается.
* **Геометрия — из таблицы логической страницы PCL 5.** Для A4 при
  600 dpi печатная область 4676 × 6814 точек со смещением (142, 100).
  Логическая страница PCL уже, чем лист, и это частый источник
  съехавших на четверть дюйма полей.

### Грабли Unidrv, на которых драйвер падал

Парсер GPD не сообщает об ошибках: неправильная строка либо молча
выпадает, либо роняет спулер уже во время печати.

* **Голый `%` в команде роняет спулер.** В скомпилированном GPD ссылка на
  параметр хранится как `%0001`, а в кавычках GPD `%` — escape (`%%` —
  процент, `%<` — литеральный `<`). UEL был записан хексом
  `<1B252D3132...>`, и байт `25` попадал в бинарь без экранирования.
  Unidrv читал `%-123` как параметр № −123 и падал в
  `IProcessTokenStream` (`spoolsv.exe`, `UNIDRV.DLL+0x64025`, access
  violation) на первой же команде любого задания. Правильно —
  `"<1B>%%-12345X"`, как в микрософтовском `PJL.GPD`.
* **Две записи в одной строке молча выкидываются.** Значение записи
  тянется до конца строки, поэтому в
  `*Command: CmdSelect { *Order: DOC_SETUP.10 *Cmd: "<1B>&l26A" }`
  `*Cmd` съедается `*Order`-ом, и команды нет. Так пропадали все
  форматы бумаги, лотки и PJL-опции. Одна запись в однострочных скобках
  (`*Command: CmdCR { *Cmd : "<0D>" }`) работает.
* **Формат бумаги сбрасывает верхнее поле PCL** на 1/2 дюйма, поэтому
  `<Esc>&l0E` шлётся в `CmdStartPage`, после выбора формата, а не до.

Первые два пункта теперь ловит `tests/gpdcheck.py`.

## Установка (USB)

1. **Сначала подключите принтер и включите его.** Порт `USB00x`
   существует только пока Windows видит устройство — его публикует
   встроенный `usbprint.sys`, независимо от наличия драйвера.
2. Скопируйте папку `driver` на целевую машину.
3. Сначала прогоните проверку, она ничего не меняет:
   ```powershell
   .\Install-ML1250.ps1 -CheckOnly
   ```
4. Правый клик по `Install.cmd` → **Запуск от имени администратора**.

Или вручную:
```powershell
.\Install-ML1250.ps1 -PrinterName "Samsung ML-1250"
```

Порт ML-1250 установщик находит по USB VID/PID, так что второй
USB-принтер на той же машине ему не мешает. Переопределить можно через
`-PortName`, например `-PortName LPT1:` для параллельного кабеля.

### Про подпись — прочитайте, это важно

Windows **не установит** неподписанный пакет драйвера принтера. Политика
спулера `ConfigureDriverValidationLevel` не имеет уровня «разрешить
неподписанные»: самый мягкий (4, он же по умолчанию) — «Allow all validly
**signed** drivers». У `pnputil` нет ключа обхода, а
`bcdedit /set testsigning on` тут не поможет — это переключатель для
кода режима ядра, а в нашем пакете кода нет вообще.

Поэтому установщик **создаёт самоподписанный сертификат и добавляет его
в доверенные корневые центры и доверенные издатели этой машины.**
Это реальное решение о доверии: всё, подписанное этим ключом, станет
доверенным в системе. Смягчения:

* ключ 3072 бита, живёт только в момент подписи и сразу удаляется
  (если не указать `-KeepCertificate`);
* `Uninstall-ML1250.ps1` убирает сертификат из всех хранилищ;
* подписываются ровно два текстовых файла, `ml1250.inf` и `ml1250.gpd`.

Если такое неприемлемо — используйте утилиту `ml1250.exe` (ниже), она
печатает вообще без драйвера.

### Windows protected print mode

Единственное, что делает драйвер принципиально неустановимым. Когда он
включён, Windows удаляет сторонние драйверы печати из хранилища и
разрешает только IPP. По умолчанию **выключен** на 24H2/25H2, но
Microsoft обещает включить его по умолчанию в будущем. Установщик это
проверяет и отказывается работать, а не ставит наполовину.

Выключается: `Параметры → Bluetooth и устройства → Принтеры и сканеры →
Настройки принтера → Режим защищённой печати Windows → Выкл`.
Если включён групповой политикой — только через администратора домена.

## Если не печатает

Лестница, сверху вниз. Каждый шаг отсекает половину вариантов.

**0. Встроенный «Microsoft PCL6 Class Driver» пробовать не надо.**
Он есть в Windows 11 (`prnms005.inf`), и это выглядит соблазнительно, но
его рендерер `MSxpsPCL6.dll` выдаёт заголовок `) HP-PCL XL;3;0;` —
протокол класса 3.0. ML-1250 реализует только 1.1 и 2.0. Плюс он
привязывается по идентификатору `1284_CID_MS_PCL6`, которого у принтера
2000 года нет. Это тупик по построению.

**1. Жив ли принтер и канал вообще.** Проверяется без драйвера и без
нашего растра — принтер печатает собственную страницу:
```
ml1250 list                      # принтер виден как USB-устройство?
ml1250 probe --pjl               # что он сам про себя сообщает
ml1250 testprint config --usb    # конфигурационная страница принтера
```
`testprint` посылает только `@PJL TEST PRINT = CONFIG` — ни байта нашего
содержимого. Если страница вышла, порт, кабель, PJL и механика исправны,
и всё, что сломается дальше, — наше. Бонусом эта страница показывает
реальный объём памяти и список личностей принтера.

**2. Жив ли PCL-интерпретатор.**
```
ml1250 testpage --text --usb     # текст шрифтами самого принтера
```

**3. Наш растр.**
```
ml1250 testpage --usb            # рамка, шкала серого, линии разной толщины
```
Рамка показывает реальную печатную область. Если изображение съехало или
обрезано — поля подгоняются `--offset-x` / `--offset-y` (в точках, 600
на дюйм), а в драйвере теми же числами в `*PrintableOrigin` /
`*CursorOrigin`.

**4. Сложная страница не лезет в память** — симптом: страница не
выходит, выходит наполовину или принтер моргает ошибкой.
В свойствах принтера: **300 dpi**, полутон **6x6**, не «рассеивание
ошибки». Или добавьте памяти — слот SIMM в днище, до 68 МБ; после этого
имеет смысл включить «Page protection».

**5. Очередь виснет / странное поведение на переходнике USB→LPT.**
Поставьте вариант **«Samsung ML-1250 PCL5e»** (он и так по умолчанию)
вместо «(with status)» — у второго подключён PJL-монитор, которому нужен
честно двунаправленный порт.

**6. Ничего не помогло — печать мимо драйвера.**
```
ml1250 print страница.pgm --usb
```
Любой PDF/PS можно прогнать через Ghostscript в растр и отдать напрямую:
```
gswin64c -q -dBATCH -dNOPAUSE -sDEVICE=pgmraw -r600 -sOutputFile=- file.pdf | ml1250 print - --usb
```

## Утилита `ml1250.exe`

Самостоятельный exe без зависимостей. Разговаривает с принтером напрямую
через `usbprint.sys` (`GUID_DEVINTERFACE_USBPRINT`), через `\\.\LPT1`
или через существующую очередь Windows в RAW-режиме.

```
ml1250 list                          USB-принтеры и их IEEE-1284 ID
ml1250 probe [--pjl]                 что принтер сообщает о себе + статус
ml1250 send FILE [target]            отправить файл байт в байт
ml1250 print FILE... [opts] [target] отрисовать и напечатать
ml1250 testpage [opts] [target]      наша диагностическая страница
ml1250 testprint config|demo|pclfont собственная страница принтера (чистый PJL)
```

Куда печатать: `-o ФАЙЛ` | `--usb [N]` | `--dev ПУТЬ` | `--lpt 1` | `--queue "Имя"`

Параметры задания: `--lang pcl5|pclxl|smartgdi`, `--paper`, `--res 600|300`,
`--copies`, `--density`, `--economode`, `--compress auto|0|2|3`,
`--halftone cluster|bayer|fs|threshold`, `--offset-x`, `--offset-y`,
`--ret normal|enhance|gray|gray+` (это и есть «SRT»),
`--pageprotect auto|on|off` (по умолчанию не шлётся вообще),
`--xl-class 2.0|1.1`, `--no-pjl`.

Входные форматы: Netpbm (`.pbm` / `.pgm` / `.ppm`) и **PWG Raster** —
тот самый формат, который Windows шлёт IPP-принтерам, так что утилита
годится и как конвертер в связке с IPP-мостом.

`probe` — самая полезная команда: она читает IEEE-1284 device ID через
`IOCTL_USBPRINT_GET_1284_ID`, и поле `CMD:` в ответе окончательно
скажет, какие языки принтер реально понимает.

### `--lang smartgdi`

Вывод в Samsung SmartGDI (SPL1) — **не для ML-1250**, а для его
собратьев по корпусу ML-1210 / ML-1220M и для семейства
ML-4500 / ML-5000A / ML-6040, которые как раз host-based. Формат
восстановлен по `contrib/gdevgdi.c` из Ghostscript — единственному
публичному описанию. Оставлен в том числе как страховка на случай, если
конкретный экземпляр окажется с GDI-платой.

## Что проверено, а что нет

Драйвер проверен на живом ML-1250 под Windows 10 22H2 (сборка 19045).
Остальное — честно по пунктам.

**Проверено:**

* Печать через драйвер. Установка, очередь на USB-порт ML-1250 рядом
  с другим USB-принтером, тестовая GDI-страница A4 600 dpi (рамка по краю печатной
  области, кириллица, шкала серого, линии) вышла на принтере. Вывод
  драйвера в 600 dpi, 300 dpi и в альбомной ориентации снят через «печать
  в файл», разобран и отрисован обратно: порядок команд совпадает с
  `ml1250.exe`, внутри растра нет запрещённых команд.

* Байтовые потоки. Для каждого компрессора написан независимый декодер,
  и полное PCL5e-задание разбирается обратно в битмап и сравнивается
  с исходником попиксельно — во всех режимах сжатия (0 / 2 / 3 / auto).
  `make test` → 42 проверки.
* PCL-XL-поток разобран побайтово; все теги операторов, атрибутов и
  типов данных сверены с микрософтовским `PCLXL.GPD`, который лежит
  в `C:\Windows\System32\spool\drivers\x64\3\`.
* `ml1250.inf` разбирается парсером самой Windows (SetupAPI,
  `INF_STYLE_WIN4`) — `tests/infcheck.c`; имена секций проверены на
  отсутствие коллизий с `ntprint.inf`. Структура INF скопирована с живого
  `prnge001.inf`, а имена core-секций и GUID — из `ntprint.inf` этой же
  сборки Windows.
* `ml1250.gpd` проходит структурную проверку (`tests/gpdcheck.py`): баланс
  скобок, `*DefaultOption` указывает на существующую опцию, все имена
  команд есть в словаре Unidrv, секции `*Order` валидны, hex-блоки целые,
  нет двух записей в одной строке и нет голого `%` в командах (см.
  «Грабли Unidrv» выше — обе ошибки парсер проглатывает молча).
* Наличие всего необходимого в Windows 11 25H2 (сборка 26200):
  `UNIDRV.DLL`, `UNIDRVUI.DLL`, `UNIRES.DLL`, `STDNAMES.GPD`,
  `PJLMON.DLL`, секции `[UNIDRV.OEM]` / `[UNIDRV_DATA]` в `ntprint.inf`.
* Read-only режим установщика (`-CheckOnly`).

**Не проверено:**

* Поля на других форматах, кроме A4. Геометрия взята из таблицы
  логической страницы PCL 5 — если выйдет постоянное смещение, оно
  правится `--offset-x/--offset-y` в утилите и `*PrintableOrigin` /
  `*CursorOrigin` в GPD.
* Поведение PJL-переменных на этом железе. `@PJL SET ECONOMODE` и
  `@PJL SET RET` взяты из строк самого драйвера Samsung, так что они
  почти наверняка верны; `PAGEPROTECT` не шлётся по умолчанию именно
  потому, что не проверен. По спецификации PJL неизвестные переменные
  игнорируются с предупреждением, и есть `--no-pjl`.
* Ответы принтера на PJL-запросы (`probe --pjl`). Samsung использовала
  нестандартный `@PJL INFO PRINTER = ALL`; утилита пробует его и
  HP-стандартные, но молчание принтера — нормальный исход.
* Вариант «(with status)» с PJL-монитором.
* Установка на Windows 11.
* Ветка `--lang pclxl`.
